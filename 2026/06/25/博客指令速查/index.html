整理一下 Hexo 博客日常操作会用到的指令，方便自己查阅。

进入博客目录

所有 Hexo 命令都需要在这个目录下执行。

本地预览

  • hexo clean：清空缓存和已生成的 public 目录
  • hexo g：generate 的缩写，生成静态网页
  • hexo s：server 的缩写，启动本地预览服务器，默认地址 http://localhost:4000

部署到 GitHub Pages

  • hexo d：deploy 的缩写，把生成好的 public/ 目录推送到 GitHub Pages

创作一篇新博客

方式一：用命令创建（推荐）

会在 source/_posts/ 下自动生成一个 .md 文件，文件名就是文章标题。

文章内容写什么

文章正文使用 Markdown 语法，常用格式：

语法 效果
# 标题 一级标题
## 标题 二级标题
**粗体** 粗体
*斜体* 斜体
- 列表项 无序列表
1. 列表项 有序列表
[链接](URL) 超链接
![图片](路径) 图片
> 引用文字 引用块

和平时直接写文章的区别

平时写文章（比如 Word、记事本）和写 Hexo 博客有以下关键区别：

  1. 必须带 Front-matter：文章开头必须有 --- 包裹的元信息块，否则 Hexo 无法识别标题、日期、分类等。平时写文章直接写标题就行，但博客必须声明这些元数据。

  2. 用 Markdown 而非富文本：平时用 Word 点击加粗、插入图片；博客里全部用纯文本符号表示格式，比如 **粗体**、![描述](图片路径)。好处是纯文本方便版本管理和迁移。

  3. 图片需要放在 source 目录：平时拖拽图片就行；博客里图片要放在 source/img/ 下，然后在 Markdown 里用 /img/文件名.jpg 引用。

  4. 写完需要生成和部署：平时保存就完事；博客写完后要执行 hexo g && hexo d 生成并发布，否则网上看不到。

  5. 文件名即 URL：文章文件名会变成网页 URL 的一部分，所以建议用英文或拼音命名，避免中文文件名导致链接乱码。

代码形式的注意点

在博客里写代码 block 时需要注意：

  1. 用三个反引号包裹代码：

    常见语言名：`bash`、`cpp`、`python`、`javascript`、`json`、`yaml` 等。不写语言名则没有语法高亮。

  2. 反引号冲突：如果代码内容本身包含三个反引号，外层用四个反引号 `````` 包裹，避免冲突。

  3. 转义特殊字符：代码块内的 <、> 会被 Hexo 当作 HTML 标签解析，如果代码里有 HTML 尖括号（比如 #include <iostream>），确保在代码块内部，Markdown 解析器一般不会干扰。但如果在行内代码中，用反引号包裹：`#include <iostream>`。

  4. YAML 头部中的特殊字符：Front-matter 里如果标题包含冒号 :、井号 # 等特殊字符，必须用引号包裹标题，比如 title: "我的：文章"，否则 YAML 解析会报错。

  5. 缩进用空格不用 Tab：代码块内的缩进建议用空格（2 或 4 个），Tab 在不同编辑器下宽度不一致，可能导致 Markdown 列表内嵌代码块时解析异常。

  6. 行内代码：正文中提到变量名、命令、文件名时，用反引号包裹，如 `hexo g`，会显示为 hexo g，更清晰。

其他常用指令

命令 作用
hexo new page "页面名" 新建一个页面，比如 about、links
hexo clean 清空缓存和 public 目录
hexo generate / hexo g 生成静态网站
hexo server / hexo s 启动本地预览服务器
hexo deploy / hexo d 部署到远程服务器
hexo list <type> 列出文章、页面、分类、标签等
hexo version 查看 Hexo 版本

小提示

  • && 表示前一条命令成功后再执行下一条
  • 修改配置或文章后，建议先 hexo clean 再生成，避免缓存导致效果不更新
  • 本地预览没问题后，再执行部署命令
  • 文章写完保存后，hexo s 运行中的本地预览会自动刷新，无需重启
  • 想置顶文章，在 Front-matter 加 sticky: 1 即可
