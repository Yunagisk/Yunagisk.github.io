三、.gitignore 机制与通配符详解

.gitignore 是一个纯文本文件，用来告诉 Git 哪些文件或文件夹不需要纳入版本控制。

1. 核心语法规则与示例

语法 / 通配符 说明 示例 作用
# 注释行 # 这是注释 被 Git 忽略不处理
/（前缀） 仅匹配仓库根目录下的文件/文件夹 /Library/ 只忽略根目录下的 Library，不影响子目录
/（后缀） 专门用于指定文件夹 Temp/ 匹配名为 Temp 的文件夹及其内部所有内容
* 匹配零个或多个任意字符 *.sln 忽略所有以 .sln 结尾的项目文件
** 匹配任意层级的嵌套子目录 **/Library/ 忽略根目录、Demo_2D/Library/ 等任何深度下的 Library
[] 字符集匹配（通常用来忽略大小写） [L-l]ibrary/ 同时拦截 Library/ 和 library/

2. 为什么 Unity 项目必须配置 .gitignore？

  • 体积与限重：Unity 的 Library 文件夹包含了编译生成的资源缓存，动辄数 GB，且经常产生超过 100MB 的单体库文件（如 Burst 编译库 libburst-llvm.dylib），这会触发 GitHub 的 100MB 硬性限制导致推送失败。
  • 平台无关性：Library/、Temp/、Logs/ 和 .vs/ 等均属于本地临时文件。其他人在拉取代码时，Unity 会根据你的 Assets、Packages 和 ProjectSettings 自动重新构建全新的 Library，无需上传共享。

📚 这篇博客只是速查表，Git 的功能远不止这些（比如 git rebase、git stash、git cherry-pick 等进阶用法）。后续遇到常用命令会持续补充到这里。
